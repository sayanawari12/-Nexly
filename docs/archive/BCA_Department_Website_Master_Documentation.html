01. Core Architecture Project Overview

01 Project Overview

1.1 Platform Vision & Core Mission

The BCA Department Website is a next-generation, unified digital learning platform engineered specifically for Computer Applications undergraduate students. It bridges the gap between theoretical university curriculum and real-world software engineering practice by providing an integrated ecosystem containing course notes, semester past papers, interactive code execution sandboxes, structured technology learning hubs, contest arenas, and real-time skill analytics.

Primary Goals
  • Deliver a centralized digital hub for all 6 BCA semesters.
  • Eliminate fragmented learning materials via structured syllabus nodes.
  • Embed interactive code execution directly inside lesson modules.
  • Provide real-time progress tracking, streaks, and skill radars.
Core Objectives
  • Sub-second UI navigation powered by React lazy route splitting.
  • Enterprise security using JWT token rotation and RBAC controls.
  • Zero-setup online code compiler supporting 10+ languages.
  • High-resolution PDF viewer for past papers & question banks.

03. User Experience Navigation Flow

03 Complete Navigation Flow

The BCA Department Platform enforces a structured user journey designed to maximize student engagement, minimize friction during learning sessions, and seamlessly transition from theoretical study to interactive coding practice.

3.1 Detailed User Journey Matrix

Phase 1: Entry & Authentication

Unauthenticated guests land on the high-impact Home page (`/`). Upon attempting to access protected resources, the `ProtectedRoute` guard intercepts the navigation and redirects to `/login`. Upon successful OAuth or JWT credential validation, the session token is stored in memory and HTTP-only cookies.

Phase 2: Curriculum Exploration

From the Central Dashboard (`/dashboard`), students select their active semester (Semester 1 through 6). The application loads specific subject portals (`/curriculum/semester-2/data-structures`), rendering unit cards, downloadable PDF syllabus files, and structured chapter nodes.

Phase 3: Interactive Practice

Within chapter lessons, students click "Try in Compiler" which loads the live Monaco editor (`/practice`). Code snippets are executed against test cases via the backend Judge0 compiler API. Output results, runtime errors, and execution metrics render instantly.

Phase 4: Quiz & Progress Recording

Upon completing practice problems, students take end-of-unit quizzes (`/technologies/cpp/quiz`). Quiz results are committed to PostgreSQL via `ProgressContext`, updating daily streaks, solved problem counts, and subject skill vectors in real time.

11. Platform Security Authentication & RBAC

11 Authentication & Security Layer

The platform employs a defense-in-depth security model featuring dual authentication mechanisms (JWT Token Family with SHA-256 rotation & Firebase Auth), bcrypt password hashing, and granular Role-Based Access Control (RBAC).

11.1 Refresh Token Rotation Flow

To protect against token theft, refresh tokens are bound to session families (`familyId` in `RefreshToken` table). Whenever a refresh token is reused after rotation, the entire session family is automatically revoked as an anti-replay security measure.

11.2 Role-Based Access Hierarchy (RBAC)

Role Enum Level Permissions Scope
USER Level 1 Access public & protected student curriculum, compiler, submit solutions.
MODERATOR Level 2 Review community questions, moderate student discussions and reports.
CONTEST_MANAGER Level 3 Create, schedule, freeze, and publish competitive coding contests.
CONTENT_REVIEWER Level 3 Edit problem statements, test cases, and publish curriculum notes.
ADMIN Level 4 Full access to administrative dashboard, user management, and system metrics.
SUPER_ADMIN Level 5 Platform configuration, feature flags, role assignments, audit log review.

11.3 Protected Route Implementation

// src/routes/ProtectedRoute.jsx
import React from 'react';
import { Navigate } from 'react-router-dom';
import { useAuth } from '../context/AuthContext';

const ProtectedRoute = ({ children, requiredRole }) => {
  const { user, loading } = useAuth();

  if (loading) return <PageLoader />;
  if (!user) return <Navigate to="/login" replace />;
  if (requiredRole && user.role !== requiredRole) return <Navigate to="/unauthorized" replace />;

  return children;
};

19. Engineering Excellence Performance

19 Performance Optimization

To achieve sub-second page loads and maintain high Lighthouse scores, the web application incorporates route-level code splitting, asset memoization, and dynamic chunking.

19.1 Route Splitting Architecture (`React.lazy`)

Instead of shipping a single monolithic JavaScript bundle, heavy page views are split into isolated chunks loaded on demand when the corresponding route is visited: 

// App.js Route Splitting Pattern
const Dashboard = lazy(() => import('./pages/Dashboard'));
const CppLearningHub = lazy(() => import('./pages/CppLearningHub'));
const ContestProblemArena = lazy(() => import('./pages/ContestProblemArena'));

function App() {
  return (
    <Suspense fallback={<PageLoader />}>
      <Routes>
        <Route path="/dashboard" element={<ProtectedRoute><Dashboard /></ProtectedRoute>} />
      </Routes>
    </Suspense>
  );
}

26 Appendix: Glossary & References

26.1 Technical Glossary

  • ACID: Atomicity, Consistency, Isolation, Durability — Relational database properties guaranteed by PostgreSQL.
  • JWT: JSON Web Token — Compact, URL-safe means of representing claims between two parties.
  • ORM: Object-Relational Mapping — Technique for querying databases using object-oriented code (Prisma).
  • RBAC: Role-Based Access Control — Restricting platform access based on user roles.
  • SPA: Single Page Application — Web site that interacts dynamically by rewriting current web page rather than loading new pages.
